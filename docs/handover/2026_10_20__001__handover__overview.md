## 新项目启动建议

1. 干净起点:`create-tauri-app` 后 **先验证空壳 `tauri dev` 跑通**,再引入 M0 变更,**一次只引入一个变量**(先依赖+插件 → 跑通 → 再色板 → 跑通 …)。这是本次最大的教训:多变量同时引入后白屏无法归因
2. 初始即 `git init`,每个可用状态提交——本次无法回退到"最后已知好状态"是致命伤
3. M0 按清单照抄(见 002 文档),完成后进入 M1(账号管理)
4. 保留以下防护设施(设计文档见 003):mount 前置、页面错误红条、vite config 稳定性原则、devtools feature + 启动自动打开、dev 看门狗
