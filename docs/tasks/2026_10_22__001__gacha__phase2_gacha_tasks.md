## 实施备注(2026-10-22)

- **页面范围(用户要求)**:仅展示当前账号(随左下角头像菜单切换),进入/切换只从磁盘恢复数据展示;网络刷新仅手动(全量拉取代价高,之后增量秒级完成)。
- **卡池语义勘误(验收中发现)**:400 为「祈愿二」(5.0 双角色池第二条,与 301 共享保底;Snap 注释 SpecialActivityAvatar),500 为「集录」(社区共识,Snap 枚举名 ActivityCity 有误导);UI 展示层将 301+400 合并为「角色」分组统计——与 UIGF 的 400→uigf_gacha_type 301 归并规则同源,导出仍保留原始 gacha_type。
- **布局演进**:初版"池 tab + 统计隔离"经用户反馈改为**卡池卡片平铺**(Dashboard 同风格 auto-fill 网格),每卡自带统计(五星/四星/五星率/距上次五星/最早记录)与 50 条分页列表。
- 写文件经 Rust `save_text_file` command(避免为此引入 fs 插件);导出文件写入经 dialog 选路径。
- 国际服直接拉取仍不支持(缺 OSLK2 盐,入口报错提示)。

## UIGF 导入补充(2026-10-22,用户要求)

- **导入(仅 v4,不兼容旧版)**:Gacha 页「导入」选文件 → 版本门控(`^v4.\d+`)→ hk4e 必填字段行过滤 → 与本地按 id 去重合并(BigInt 排序)持久化;读文件走 Rust `read_text_file`(免引 fs 插件)。
- **导入范围收紧(实测反馈)**:仅接受**当前账号**角色的 uid——先收紧到"已添加账号"仍会出现"导入成功但本页看不到"(记录在其他账号角色下),最终收紧到当前账号;被跳过的 uid 在反馈中列出。杜绝不可见且无法清除的孤儿数据。
- **操作层级统一(实测反馈)**:角色卡纯展示;页面级按钮组 导入/导出(ghost 成对)/拉取记录(primary)/清空记录(danger 实底),导出为当前账号全部角色的**单份多 uid 文件**(`UIGF_v4.0_{uid}.json` / 多角色 `{n}roles.json`),清空带确认弹窗。
- Settings 关于卡按 UIGF-org 要求提供 [uigf.org](https://uigf.org/) 声明链接。
- 真机验收:往返导入(去重 0 新增)、版本门控拒旧版、跨账号 uid 跳过、多角色单文件导出。

## 实施约束

- 仅国服 SToken 换取路径;国际服在 UI 中禁用刷新并提示(导出仍可用已有数据)。
- 分页限速 300ms;请求全部走 `miHoYoRequest`(tauri-fetch 通道)。
- 列表分页渲染,不引虚拟滚动等新依赖。
