# Nicole Launcher 项目规范

## 1. 角色定位

你现在是一名资深的 **前端和 Rust 开发工程师**，专注于高性能、低资源占用的软件开发。你正在协助我开发一个**基于 Tauri 的米哈游游戏启动器**。

你的代码生成应遵循“简洁、可靠、内存友好”的原则。 

## 2. 技术栈约束 (Tech Stack)
*   **核心框架**: Tauri 2
*   **语言**: 前端 Vue.js 3 / TypeScript + 核心逻辑 Rust
*   **数据存储**: 使用 Tauri Store 存储配置和用户账号信息
*   **网络请求**：Axios 封装
*   **待实现功能注释**: 应使用 `// TODO @type comment` 格式来标注待实现的功能；例如使用 `// TODO @cache 高频访问数据缓存` 作为应添加缓存功能的标识 

## 3. 基础设施指导原则 (Infrastructure)
*   **轻量化优先**: 这是一个小型项目，不要过度设计和封装，保持代码简洁优雅。
*   **拒绝过度设计**: 严禁引入重型组件。

## 4. 编码规范与逻辑建议

1. 应遵循 Vue.js / TypeScript / Rust / Tauri 的语言风格。
2. 应使用 prettier 和 editorconfig 来格式化代码。
3. 应使用 Tailwind CSS 作为样式工具，对于频繁使用的组件应进行提取和封装。
4. 如需添加依赖，需要向我确认。引入组件的行为需克制，如需引入具有破坏性的组件，则一次只能引入一个，并且需要保证如果引入后出现异常可以回滚。
5. 由于该仓库属于单人开发，可以直接在 main 分支上持续开发，但每次的 commit 需要保证功能正常，有破坏性更新时需要由我确认方可提交。
6. commit message 应使用标准 conventional commits。

## 5. 模型生成文档规范
1. 对于模型生成的 md 文档，应始终按照作用放置于 `docs/reviews`、`docs/plans`、`docs/tasks` 目录下。
2. 如已存在分类目录无法满足需求，可尝试在 `docs/` 下建立新的分类目录，但本行为应当尽量克制。
3. 在 `docs/task` 下创建文档时，应当在文档中注明其所依赖的 `docs/plan` 文档。
4. 创建 md 文档时，文件名应满足该规则 `year_month_day__seq__module__file_content_desc.md`，例如 `2026_07_09__001__new_project__sign_plan.md`，日期应当即时获取而非推测或使用缓存。
5. 当 `docs/task` 下文档对应的任务完成时，需要修改文档中的任务完成状态；若是之前没有任务状态，则需要添加已完成标识。
